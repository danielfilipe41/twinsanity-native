# Building for the web (wasm32)

The build has the slot for it (`PLATFORM=web`), the platform layer it shares with the Linux port and both renderer blob
sets, but the web build is not finished. Shared requirements: [BUILDING.md](BUILDING.md).

What exists:

- `PLATFORM=web python3 configure.py` writes a wasm32 build with the emsdk's `em++`, on the same `src/platform/sdl3` layer
  over the null stubs, and `ninja compile` is its check that every TU compiles for wasm32.
- The renderers are `webgl` (bgfx's GL ES renderer, GLSL ES 300) and `webgpu` (WGSL), both blob sets generated by
  `tools/build_shaders.py --platform web` and checked in.

What is missing before it links into a `game.html`:

1. Emscripten (emsdk 4.x, which carries SDL3 as `-sUSE_SDL=3`): source `emsdk_env.sh` so `em++` is on `PATH`.
2. bgfx, bx and bimg built for wasm: `cd third_party/bgfx && make config=release32 -C .build/projects/gmake-web`, or
   point `BGFX_WEB_PREFIX` at wherever its libraries land.
3. The retail data as wasm. `tools/host_data.py` converts the split's MIPS data asm into x86 objects for the Linux
   build, and wasm cannot link those; it needs a wasm target (C arrays, or wasm assembly) first.

The page itself is a separate container, not something the game opens from inside `disc/`: it offers the data folder (or
the extracted ISO) and the renderer, then runs the build.
